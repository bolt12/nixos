# hetzner-hub, Hetzner Cloud VM (WireGuard hub + tunnel DNS)

Public entry point for the fleet after the home ISP switch removed the public IP.
Two roles:

1. **WireGuard hub** at `10.100.0.1/24`, port `51820`. Reuses the RPi's server
   key and VPN address, so every existing peer keeps working; only endpoints
   moved here. Peer table in `wireguard.nix`.
2. **Adblock resolver** (unbound + Hagezi RPZ) served **only over the tunnel** on
   `10.100.0.1`. Config via the shared `services.adblockDns` module; hardening in
   `dns.nix`.

The RPi keeps Tang + a LAN-only copy of the same resolver. ninho resolves via the
RPi's LAN IP; remote clients resolve via `10.100.0.1` over the tunnel.

## Files

- `disko.nix` BIOS GPT layout (1M EF02 boot partition + ext4 root, GRUB). Wipes
  the disk on install. This VM boots legacy BIOS (confirmed by pre-flight).
- `hardware-configuration.nix` generated by nixos-anywhere (stub until then).
- `networking.nix` systemd-networkd, DHCP v4 + static v6 via `fe80::1`.
- `wireguard.nix` hub, NAT masquerade, public firewall (22/tcp + 51820/udp only).
- `dns.nix` adblock resolver options (tunnel-only bind, refuse-by-default ACL).
- `configuration.nix` bootloader, SSH, packages, stateVersion.

## First install (from ninho or the laptop)

Prerequisites: SSH as root to the live Ubuntu box, and the RPi's WireGuard
private key.

```bash
# 0. Pre-flight (read-only). Confirms boot mode, disk id, NIC name.
ssh root@2.28.9.140 '[ -d /sys/firmware/efi ] && echo UEFI || echo BIOS; \
  ls -l /dev/disk/by-id; lsblk; ip -o link'
#   Confirmed on this VM: BIOS, /dev/sda (scsi-0QEMU_QEMU_HARDDISK_124945215),
#   eth0. disko.nix/configuration.nix are already set for BIOS + GRUB. If a
#   rebuild ever reports UEFI, switch disko to an ESP + systemd-boot instead.

# 1. Stage the REUSED WireGuard key for --extra-files.
temp=$(mktemp -d)
install -d -m0700 "$temp/etc/wireguard"
ssh root@<rpi-lan-ip> cat /etc/wireguard/private > "$temp/etc/wireguard/private"
chmod 0600 "$temp/etc/wireguard/private"
#   Sanity: the pubkey must equal constants.network.wireguard.serverPubKey:
wg pubkey < "$temp/etc/wireguard/private"

# 2. The stub hardware-configuration.nix is already git-tracked (flakes ignore
#    untracked files); nixos-anywhere overwrites it in the next step.

# 3. Install (builds locally; do NOT --build-on-remote on a small plan).
nix run github:nix-community/nixos-anywhere -- \
  --generate-hardware-config nixos-generate-config \
    ./system/machine/hetzner/hardware-configuration.nix \
  --extra-files "$temp" \
  --flake .#hetzner \
  --target-host root@2.28.9.140
rm -rf "$temp"

# 4. Commit the generated hardware config.
git add system/machine/hetzner/hardware-configuration.nix
git commit -m "hetzner: nixos-anywhere hardware config"
```

## Verify before cutover

SSH stays up regardless (port 22 is public, independent of wg0):

```bash
ssh root@2.28.9.140 wg show                 # hub is listening
dig @2.28.9.140 example.com                 # MUST refuse/timeout (no open resolver)
```

## Cutover

Repoint each client's endpoint to `2.28.9.140`, then retire the RPi's WG server:

1. Rebuild ninho, bolt-nixos, steam-deck HM (endpoints already point here in the
   flake).
2. Update the endpoint on each external device (Android x2, Supernote, Pollard
   macOS). Key is reused, so the server pubkey is unchanged; only the endpoint
   changes.
3. Confirm per client: `wg show` handshake, `ping 10.100.0.1`, DNS resolves.
4. Retire the RPi WG server: `colmena apply --on rpi-5 --impure`.

Over the tunnel afterwards: `dig @10.100.0.1 doubleclick.net` returns NXDOMAIN
(blocklist active), a normal domain resolves, and a full-tunnel client reaches
the internet.
